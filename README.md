# Ganttraah

גאנט תכנית עבודה פנימי לענף תכנית ההתרעה.

> להמשך פיתוח (שיחה חדשה או מפתח חדש): להתחיל מ-[HANDOFF.md](HANDOFF.md). האפיון המלא: [docs/spec.md](docs/spec.md).

מערכת פנימית לניהול תכניות עבודה: פרויקטים, היררכיית משימות, תלויות, גאנט מימין לשמאל, מפת השפעות, הדמיית "מה אם" ותצוגת מנהלים.
המערכת רצה על שרת אחד ברשת הפנימית, ונכנסים אליה מהדפדפן (Chrome או Edge). אין צורך באינטרנט.

---

## מה יש במערכת

| מסך | מה עושים בו |
|---|---|
| **תכנית עבודה** | גאנט של כל הפרויקטים. יצירה ועריכה של משימות, תתי-משימות ואבני דרך. גרירת פס מזיזה משימה, משיכת הקצה השמאלי משנה את המשך, וגרירה מהעיגול שבקצה הפס אל משימה אחרת יוצרת תלות. לחיצה על משימה מסמנת בכתום את כל מה שמשפיע עליה ובסגול את כל מה שמושפע ממנה. |
| **מפת השפעות** | משימה אחת במרכז, ממוקמת בתוך ההיררכיה שלה. מימין השרשרת שמשפיעה עליה, משמאל השרשרת שמושפעת ממנה. "מה אם": מה יקרה אם המשימה תתעכב ב-N ימים, או לא תתבצע בכלל. |
| **תצוגת מנהלים** | תצוגה נקייה לקריאה בלבד, להצגה למנהלים וללקוחות. סינון לפי פרויקט או אב-משימה, בחירת רמת פירוט, מדדים בראש המסך ומסך מלא. |
| **היסטוריה** | כל שינוי נרשם: מי, מה, מתי, ואילו משימות זזו בעקבותיו. |
| **הגדרות** | ימי עבודה, חגים (מחושבים אוטומטית מהלוח העברי), ימים מיוחדים, משתמשים והרשאות. |

### איך התזמון עובד
- המשך נספר בימי עבודה (ברירת המחדל: א'-ה', בלי חגים).
- סוגי תלות: **סיום ← התחלה** (הנפוץ), **התחלה ← התחלה**, **סיום ← סיום**. אפשר להוסיף השהיה, חיובית או שלילית, בימים.
- כשמשימה מתעכבת או מתארכת, כל המשימות שתלויות בה זזות אוטומטית, גם בפרויקטים אחרים.
- **אב-משימה** (משימה שיש בה תתי-משימות) מקבלת את התאריכים ואת אחוז ההתקדמות שלה מתתי-המשימות. תלות על אב-משימה חלה על כל מה שבתוכה.
- גרירת משימה קובעת לה "לא להתחיל לפני" התאריך שנבחר. בפאנל של המשימה אפשר לבטל את זה ולחזור לחישוב אוטומטי.
- **קו בסיס**: שמירת התכנון הנוכחי כ"מקורי", כדי לראות בהמשך כמה כל משימה זזה ממנו (בעריכת הפרויקט).
- **נתיב קריטי**: המשימות שכל עיכוב בהן מזיז את סיום הפרויקט.

### כניסה והרשאות
- **כניסה:** בכל כניסה מגיעים לדף "שלום, בחר/י את הצוות שלך" עם העץ הארגוני (הנהלת הענף › 6 מדורים › 3 צוותים בכל מדור), ובוחרים יחידה. אין סיסמה. יש גם "כניסה לצפייה בלבד".
- **צפייה:** כולם רואים את כל התוכנית.
- **עריכה:** יחידה עורכת משימות שבאחריותה ובאחריות היחידות שמתחתיה. משימה בלי אחראי מקבלת את האחראי של אב-המשימה שלה.
- **הנהלת הענף** עורכת הכול: פרויקטים, משימות ברמה העליונה, לוח עבודה ומבנה ארגוני (הגדרות › מבנה ארגוני).
- **תלות:** כדי ליצור תלות, צריך הרשאה על המשימה שמושפעת ממנה, כי התלות משנה את התאריכים שלה.
- **אחראי:** נבחר מרשימת היחידות, ולא מוקלד.
- **סינון:** הכפתור "אחראים" מציג רק משימות של יחידה אחת או יותר.

---|---|
| צופה | לראות הכול, כולל מפת השפעות, הדמיות ותצוגת מנהלים |
| עורך | גם ליצור ולשנות פרויקטים, משימות ותלויות |
| מנהל מערכת | גם לנהל משתמשים, לוח עבודה ומחיקת פרויקטים |

## התקנה ברשת הסגורה (לצוות התפעול)

הכנת החבילות נעשית על מחשב שמחובר לאינטרנט:

```
powershell -ExecutionPolicy Bypass -File deploy\build-offline.ps1
```

הסקריפט יוצר בתיקייה `deploy\out`:
- `gantraah-<גרסה>-node.zip`: המערכת עם כל הספריות שלה. דורשת רק Node.js 20 ומעלה.
- `gantraah-<גרסה>-images.tar`: אימג'ים של Docker (המערכת + PostgreSQL). נוצר רק אם Docker פועל במחשב שמכין את החבילה.

מעבירים לרשת הסגורה את אחד מהקבצים, לפי הפרוצדורה הרגילה.

### אפשרות א': Docker + PostgreSQL (מומלץ לשרת קבוע)
```
docker load -i gantraah-<גרסה>-images.tar
```
מחלצים את קובץ ה-zip, ובתיקייה `docker` שבתוכו:
1. מעתיקים את `compose.env.example` ל-`compose.env` וממלאים סיסמאות.
2. מריצים: `docker compose --env-file compose.env up -d`
3. נכנסים מהדפדפן לכתובת השרת (פורט 80 כברירת מחדל).

**גיבוי:** `backup.ps1` (באותה תיקייה) שומר dump יומי ומוחק גיבויים בני יותר מ-30 יום. מומלץ להריץ אותו כמשימה מתוזמנת ב-Windows.
**שחזור:** `Get-Content backup.sql | docker compose --env-file compose.env exec -T db psql -U gantraah -d gantraah`

### אפשרות ב': Node.js בלבד (בלי Docker)
1. מחלצים את קובץ ה-zip לתיקייה בשרת, למשל `D:\Ganttraah`.
2. מעתיקים את `.env.example` ל-`.env` ועורכים אותו:
   - `DATABASE_URL`: כתובת ה-PostgreSQL. **אם משאירים ריק**, המערכת משתמשת במסד נתונים מובנה שנשמר בתיקייה `data`, בלי שום התקנה נוספת.
   - `ADMIN_PASSWORD`: סיסמת המנהל הראשון.
   - `PORT`: הפורט (ברירת מחדל 8080).
3. מפעילים את `start-gantraah.cmd`. כדי שהמערכת תעלה מחדש אחרי הפעלה מחדש של השרת, מגדירים אותו כמשימה מתוזמנת "At startup" או כשירות Windows.

גיבוי במצב המובנה: עוצרים את השרת ומעתיקים את התיקייה `data`.

### עדכון גרסה
- **Docker:** טוענים את קובץ ה-tar החדש ומריצים `docker compose --env-file compose.env up -d`. הנתונים נשמרים ב-volume.
- **Node:** מחליפים את התיקיות `server` ו-`client`, ולא נוגעים ב-`.env` ובתיקייה `data`. אחר כך מפעילים מחדש.

מבנה מסד הנתונים מתעדכן אוטומטית בכל הפעלה.

### משתמש ראשון
בהפעלה הראשונה, כשאין עדיין משתמשים, נוצר משתמש מנהל מערכת לפי `ADMIN_USERNAME` ו-`ADMIN_PASSWORD`. אם לא הוגדרה סיסמה, המערכת יוצרת סיסמה אקראית ושומרת אותה ב-`data/initial-admin.txt`. אחרי הכניסה הראשונה כדאי להחליף את הסיסמה ולמחוק את הקובץ.

### בדיקת תקינות
`http://<שרת>/healthz` מחזיר `{"ok":true}` כשהמערכת ומסד הנתונים תקינים.

## קובץ הדגמה (HTML אחד)

`deploy\out\Ganttraah-demo.html` היא המערכת המלאה בקובץ אחד, להצגה במחשב בלי שרת ובלי התקנה. פותחים אותו בלחיצה כפולה (Chrome או Edge).
- הכול עובד: דף הכניסה, הגאנט, עריכה וגרירה, תלויות, מפת השפעות ו"מה אם", תצוגת מנהלים, היסטוריה, ביטול והסיור. מנוע התזמון זהה לזה של השרת.
- הנתונים הם נתוני דוגמה. שינויים נשמרים רק בדפדפן שבו פותחים את הקובץ, ולא משותפים עם אף אחד. הכפתור "איפוס" ליד התווית "הדגמה" מחזיר את נתוני הדוגמה.
- יוצרים אותו מחדש עם `npm --prefix client run build:demo`. הסקריפט `deploy\build-offline.ps1` יוצר אותו גם כן.

## פיתוח

הדרך הקלה: לחיצה כפולה על **`start.bat`** בתיקייה הראשית.
- `start.bat`: מתקין חבילות אם חסרות, בונה את הממשק, מפעיל את השרת ופותח את הדפדפן. אם המערכת כבר פועלת, הוא רק פותח את הדפדפן. סוגרים את החלון כדי לעצור.
- `start.bat dev`: מצב פיתוח. נפתחים שני חלונות: השרת, שעולה מחדש בכל שינוי בקוד שלו, והממשק בכתובת http://localhost:5173, שמתרענן בכל שינוי.

או ידנית:
```
npm run install:all     # התקנת חבילות לשרת ולממשק
npm run build           # בניית הממשק
npm start               # הפעלת השרת: http://localhost:8080
```
פיתוח עם טעינה חיה: `npm run dev:server` בחלון אחד ו-`npm run dev:client` בחלון שני (http://localhost:5173).

### מבנה הקוד
```
server/src/
  index.js       הפעלת השרת, קבצים סטטיים ו-WebSocket לעדכונים חיים
  api.js         כל נקודות ה-API
  scheduler.js   מנוע התזמון: מעבר קדימה, roll-up, נתיב קריטי
  calendar.js    לוח עבודה וחגים (לוח עברי מובנה ב-Node, בלי ספריות)
  impact.js      מפת השפעות והדמיית "מה אם"
  store.js       טעינה, טרנזקציות והיסטוריית שינויים
  auth.js        משתמשים, סיסמאות (scrypt) ו-sessions
  db.js          PostgreSQL או PGlite (מסד מובנה)
  schema.sql     מבנה מסד הנתונים
  seed.js        נתוני דוגמה (SEED_DEMO=true)
client/src/
  components/Gantt.tsx       רכיב הגאנט (SVG, מימין לשמאל)
  components/FocusView.tsx   מפת השפעות ו"מה אם"
  components/PresentView.tsx תצוגת מנהלים
  model.ts                   מודל הנתונים בצד הלקוח
```
