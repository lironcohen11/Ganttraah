# Ganttraah: העברה לרשת הפנימית

מסמך עבודה ליום ההעברה. הוא מסודר לפי הסדר שבו עובדים:
1. מה צריך לברר לפני.
2. מה מביאים.
3. איך מתקינים.
4. איך מתחזקים.

**גרסה:** 1.6.1 · **עודכן:** 12.11.2026

---

## 0. בקצרה

- **מה המערכת:** שרת Node.js אחד שמגיש גם את הממשק וגם את ה-API, על פורט אחד (ברירת מחדל 8080).
- **המשתמשים:** נכנסים מ-Chrome או Edge, ולא מתקינים כלום בעמדות.
- **בלי אינטרנט:** המערכת לא פונה החוצה בשום שלב. הגופן, החגים והספריות כבר בתוכה.
- **מסד הנתונים, אחת משתי אפשרויות:**
  - **מובנה (PGlite):** תיקייה `data\pglite` ליד המערכת. לא צריך להתקין כלום, אבל רק תהליך אחד יכול לפתוח אותה, והגיבוי דורש עצירה של כמה שניות. השרת שומר לידה קובץ נעילה, `data\pglite.lock`: שרת שני על אותה תיקייה ייעצר עם הודעה ולא יפגע בנתונים. אחרי קריסה הנעילה משתחררת לבד בהפעלה הבאה.
  - **PostgreSQL של הארגון:** מגדירים `DATABASE_URL`, ומקבלים גיבוי וניהול כמו בכל מסד אחר.
- **מיגרציות:** רצות לבד בכל הפעלה. אין שלב נפרד של "עדכון מסד".
- **בדיקת תקינות:** `GET /healthz` מחזיר `{"ok":true,"db":"embedded"}` או `"db":"postgres"`.

## 3. התקנה על שרת Windows (Node + מסד מובנה). הדרך הפשוטה

מבצעים כמנהל (Administrator). בכל הדוגמאות התיקייה היא `D:\Ganttraah`.

1. **Node.js:**
   ```
   node -v
   ```
   צריך להחזיר `v20` ומעלה. אם לא, מתקינים את ה-msi ופותחים חלון חדש.
2. **חילוץ:** מחלצים את `gantraah-1.6.1-node.zip` ל-`D:\Ganttraah`.
3. **הגדרות:**
   ```
   copy .env.example .env
   ```
   ועורכים את `.env`:
   ```
   PORT=8080
   DATABASE_URL=
   SEED_DEMO=false
   COOKIE_SECURE=false
   ```
   - **`DATABASE_URL`:** ריק = מסד מובנה בתיקייה `data`.
   - **`COOKIE_SECURE`:** משנים ל-`true` רק אם נכנסים דרך HTTPS.
4. **הרצה ראשונה, ידנית:** מריצים את `start-gantraah.cmd`, ומהשרת עצמו פותחים `http://localhost:8080/healthz`. צריך לחזור `{"ok":true,...}`.
   - **הלוג:** נכתב ל-`D:\Ganttraah\logs\server.log`.
   - **סגירה:** סוגרים את החלון.
5. **הפעלה אוטומטית עם עליית השרת**, בלי כלים נוספים:
   ```
   schtasks /Create /TN "Ganttraah" /TR "\"D:\Ganttraah\start-gantraah.cmd\"" /SC ONSTART /RU SYSTEM /RL HIGHEST /F
   schtasks /Run /TN "Ganttraah"
   ```
   - **מה זה עושה:** המשימה עולה עם המחשב, גם בלי שמישהו מחובר.
   - **עצירה והפעלה:** `schtasks /End /TN "Ganttraah"`, ואחר כך `schtasks /Run /TN "Ganttraah"`.
   - **להעדיף שירות Windows אמיתי?** אם מותר להכניס את `nssm.exe`:
     ```
     nssm install Ganttraah "C:\Program Files\nodejs\node.exe" "server\src\index.js"
     ```
     ואחר כך `AppDirectory=D:\Ganttraah`.
6. **חומת אש:** פותחים את הפורט רק ברשת הפנימית:
   ```
   netsh advfirewall firewall add rule name="Ganttraah" dir=in action=allow protocol=TCP localport=8080
   ```
7. **בדיקה מעמדה:** `http://<שם-השרת>:8080`.
   - **מה אמור להופיע:** דף "שלום, בחר/י את המסגרת שלך", ריק מתוכניות.
   - **כניסה כהנהלת הענף:** הסיסמה `ליורד`. **מחליפים אותה מיד** בהגדרות › מבנה ארגוני והרשאות › "החלף/י סיסמה".
8. **מתחילים לעבוד:**
   1. הנהלת הענף מתאימה את המבנה הארגוני (שמות אמיתיים).
   2. יוצרים פרויקטים.
   3. אפשר לייבא מ-Excel ("קובץ" › "ייבוא").

### 3א. עם PostgreSQL של הארגון (במקום המסד המובנה)
1. **הכנה אצל ה-DBA:** מסד ריק ומשתמש עם הרשאות מלאות עליו:
   ```
   CREATE DATABASE ganttraah;
   CREATE USER ganttraah WITH PASSWORD '...';
   GRANT ALL ON DATABASE ganttraah TO ganttraah;
   ```
   ב-PostgreSQL 15 ומעלה צריך גם הרשאה על הסכימה public.
2. **ב-`.env`:**
   ```
   DATABASE_URL=postgres://ganttraah:<סיסמה>@<שרת>:5432/ganttraah
   ```
3. **בהפעלה:** הטבלאות נוצרות לבד, ו-`/healthz` מחזיר `"db":"postgres"`.
4. **גיבוי:** `pg_dump` הרגיל של הארגון.

### 3ב. שרת Linux
אותם צעדים, עם systemd. הקובץ `/etc/systemd/system/ganttraah.service`:
```
[Unit]
Description=Ganttraah
After=network.target

[Service]
WorkingDirectory=/opt/ganttraah
ExecStart=/usr/bin/node server/src/index.js
Restart=always
User=ganttraah

[Install]
WantedBy=multi-user.target
```
ואז `systemctl enable --now ganttraah`. הלוג נמצא ב-`journalctl -u ganttraah`.

## 4. כתובת קבועה ו-HTTPS (reverse proxy)

- **ה-proxy מעביר לפורט של המערכת:** הכול נכנס דרך פורט אחד. חשוב שגם `/ws` (WebSocket) יעבור, אחרת עדכונים חיים בין משתמשים והפעמון לא יעבדו.
- **אחרי HTTPS:** משנים ב-`.env` ל-`COOKIE_SECURE=true`, ומפעילים את המערכת מחדש.

**nginx:**
```
location / {
  proxy_pass http://127.0.0.1:8080;
  proxy_http_version 1.1;
  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "upgrade";
  proxy_set_header Host $host;
}
```
**IIS:**
- **רכיבים:** ARR ו-URL Rewrite, עם התכונה "WebSocket Protocol" מותקנת.
- **הכלל:** Reverse Proxy ל-`http://localhost:8080`.

| התקנה | גיבוי | שחזור |
|---|---|---|
| **מסד מובנה** | `backup-embedded.ps1` (בתיקיית המערכת). עוצר את השירות לכמה שניות, אורז את `data\pglite` ל-zip עם תאריך, ומפעיל מחדש. מוחק גיבויים בני יותר מ-30 יום. | עוצרים את השירות, משנים שם ל-`data\pglite` הקיימת, מחלצים את ה-zip לתוך `data\`, ומפעילים. |
| **PostgreSQL** | `pg_dump` (או הגיבוי של ה-DBA). | `psql < backup.sql` לתוך מסד ריק. |
| **Docker** | `docker\backup.ps1` | ראו `README.md` |

**גיבוי לילי אוטומטי (מסד מובנה):**
```
schtasks /Create /TN "Ganttraah backup" /SC DAILY /ST 02:00 /RU SYSTEM /TR "powershell -ExecutionPolicy Bypass -File D:\Ganttraah\backup-embedded.ps1 -OutDir E:\Backups\Ganttraah" /F
```
- **איפה לשמור:** בתיקייה על דיסק אחר, או בשיתוף שמגובה בעצמו.
- **מה לבדוק:** אחרי שבוע, לבדוק שחזור אחד על מחשב בדיקה.

**ההיסטוריה:**
- **ניקוי אוטומטי:** שינויים ישנים משנה נמחקים לבד, כדי שהמסד לא יגדל בלי סוף. משנים את התקופה ב-`HISTORY_DAYS`.
- **מחיקה ידנית:** הנהלת הענף יכולה למחוק את כל ההיסטוריה מהמסך "היסטוריה".

## 6. עדכון לגרסה חדשה

1. **מכינים חבילה בחוץ:**
   ```
   deploy\build-offline.ps1 -Version x.y.z
   ```
2. **בפנים:**
   1. **גיבוי:** מריצים גיבוי (סעיף 5).
   2. **עצירה:** `schtasks /End /TN "Ganttraah"`
   3. **החלפת קבצים:** מחליפים את התיקיות `server`, `client` ו-`docs`, ואת הסקריפטים, מהחבילה החדשה.
      - **לא נוגעים ב:** `.env`, `data\`, `logs\`.
   4. **הפעלה:** `schtasks /Run /TN "Ganttraah"`. המיגרציות של המסד רצות לבד.
   5. **בדיקה:** `/healthz`, וכניסה אחת.
3. **אם משהו לא עובד:** מחזירים את הקבצים הקודמים ואת הגיבוי.
   - **חשוב:** עובדים תמיד מגיבוי. מסד שכבר עבר מיגרציה קדימה לא מבטיח עבודה עם קוד ישן.

## 10. מה כדאי לדעת (סיכונים ופערים)

- **Docker לא נבדק.** קובצי Docker קיימים, אבל לא הורצו אף פעם.
- **כניסה בלי סיסמה, חוץ מהנהלת הענף.** כל אחד ברשת יכול להיכנס בשם כל מסגרת. זו החלטה מודעת. חיבור ל-AD נמצא ברשימת הנושאים הפתוחים.
- **מסד מובנה = תהליך אחד:** אי אפשר להריץ שני שרתים על אותה תיקיית `data`, וגם לא סקריפט שפותח אותה בזמן שהשרת רץ.
- **עדכונים חיים דורשים WebSocket:** אם ה-proxy חוסם את `/ws`, הכול עובד, אבל שינויים של אחרים מופיעים רק אחרי רענון, והפעמון לא מתעדכן לבד.
- **חשבון "admin" ישן:** בהפעלה הראשונה השרת עדיין יוצר חשבון משתמש ישן בשם `admin`, מתקופה שבה הייתה כניסה עם שם משתמש. הסיסמה האקראית שלו נכתבת לקובץ `data\initial-admin.txt`. הממשק לא משתמש בחשבון הזה, אבל נתיב ההתחברות הישן עדיין קיים בשרת. אחרי ההתקנה **מוחקים את הקובץ**. מומלץ לבטל את הנתיב הזה בגרסה הבאה.
- **הנתונים מהמחשב הזה לא עוברים:** ההתקנה בפנים מתחילה ריקה, כפי שביקשת. אם יוחלט כן להעביר נתונים, מעבירים את התיקייה `data\pglite`, כשהשרת כבוי בשני הצדדים.
